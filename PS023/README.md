# PS023 - PulseFit Multi-Facility Fitness Membership & Attendance Tracking Platform

A complete Spring Boot microservices reference implementation for the PS023 use case.

## Architecture

- Service Registry / Eureka: `8761`
- API Gateway: `8080`
- Auth Service: `8081`
- Member Service: `8082`
- Subscription Service: `8083`
- Attendance Service: `8084`
- MySQL: separate database per data-owning service

Request path: **Postman -> API Gateway -> Eureka/load-balanced service -> service**.

Inter-service flow: **Attendance -> Subscription -> Member** and Attendance also validates Member directly before creating a visit.

## Technology versions

- Java 21 (recommended; Spring Boot 3.5.x is also compatible with Java 25 in current Spring Boot 3.5 documentation)
- Spring Boot 3.5.5
- Spring Cloud 2025.0.3
- Spring Cloud Gateway Server WebFlux
- Spring Cloud Netflix Eureka
- Spring Cloud LoadBalancer
- Spring Security + JWT (JJWT)
- Spring Data JPA + MySQL

Spring Cloud 2025.0.x is the release train for Spring Boot 3.5.x; this project uses the 2025.0.3 service release. See Spring's compatibility table/release notes before changing versions.

## Prerequisites

1. JDK 21 (or a supported Java 25 setup).
2. Maven 3.9+.
3. MySQL 8.x running on `localhost:3306`.
4. MySQL username/password matching the YAML files (`root` / `root`). If yours differs, edit the three service YAML files.
5. Import `postman/PS023-PulseFit.postman_collection.json` into Postman.

The JDBC URLs use `createDatabaseIfNotExist=true`, so the four databases are created automatically when the MySQL user has permission. The auth service is in-memory and does not need a database.

## Start order

Run each application as a separate process/STS application:

1. `service-registry`
2. `auth-service`
3. `member-service`
4. `subscription-service`
5. `attendance-service`
6. `api-gateway`

Wait for Eureka to show the services as `UP` before using the gateway.

### Maven commands

From the root folder, after Maven is installed:

```text
mvn clean package -DskipTests
```

Then run each module, for example:

```text
mvn -pl service-registry spring-boot:run
mvn -pl auth-service spring-boot:run
mvn -pl member-service spring-boot:run
mvn -pl subscription-service spring-boot:run
mvn -pl attendance-service spring-boot:run
mvn -pl api-gateway spring-boot:run
```

In Spring Tool Suite/Eclipse: **File -> Import -> Maven -> Existing Maven Projects**, select the extracted `PS023-PulseFit` root directory, and import all six modules.

## Postman flow

The included collection uses gateway URL `http://localhost:8080`.

1. Login as `admin` / `admin123`. The collection test script saves the JWT automatically.
2. Get members. A demo member is seeded as member `1` when the member database is empty.
3. Get plans. Three plans are seeded when the subscription database is empty.
4. Create a new member if required.
5. Create a subscription for a member and a plan.
6. Check in through Attendance. Attendance verifies the member and calls Subscription for an active subscription.
7. View attendance history.
8. Renew a subscription.

You can also register a new in-memory auth user with `/api/auth/register`, then login with that account.

## Default credentials

- Auth username: `admin`
- Auth password: `admin123`
- Second sample user: `user` / `user123`

These are development/demo credentials. Change them before any real deployment.

## Important JWT note

The same development signing secret is configured in Auth, Gateway, Member, Subscription, and Attendance so tokens generated by Auth are accepted by the protected services. For production, move the secret to an environment variable/secret manager and use asymmetric signing (RSA/EC) where appropriate.

## Troubleshooting

- **Connection refused to 8761:** start Eureka first.
- **No services in Eureka:** check that every service has `defaultZone: http://localhost:8761/eureka/` and wait 10-30 seconds.
- **Gateway 503:** verify the target service is `UP` in Eureka and the service name matches the route.
- **401 Unauthorized:** login again and ensure Postman sends `Authorization: Bearer <token>`.
- **MySQL access denied:** update username/password in member, subscription, and attendance `application.yml` files.
- **Port already in use:** stop the previous process or change the module port and its gateway route only if using direct routing; Eureka will otherwise handle service instances.
